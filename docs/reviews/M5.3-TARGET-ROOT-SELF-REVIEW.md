# M5.3 目标根创建边界自审

基线 `76601df0059805832f058f636f598e40e146bc9d`。维护者已明确要求目标根预先存在，缺失时提示用户创建。本次同步 PRODUCT、ARCHITECTURE 与 Storage Maintenance 协议，并在初次物理检查提供强类型缺失诊断。

仅 FileNotFound/DirectoryNotFound 进入缺失判定，随后检查最近存在的父级是否为普通目录，防止文件占据父路径被误报为缺失。目标根文件占位、链接和访问失败保持异常；诊断携带 Current/History slot 与稳定 code，不包含设备路径或原始异常。任何缺失检查都不创建目录、不写 journal、不改变 binding/baseline。

现有迁移 journal 的 Stage/commit/recovery 仍使用冻结的根 identity，不把恢复时根丢失映射成自动重建。允许 Stage 按既有规则创建根内归档父目录，与禁止创建目标根不冲突。当前未装配 GUI/CLI，提示由 Application 异常提供，不能声称图形提示已交付。

新增真实文件测试覆盖 Current/History 根缺失、多级父路径缺失、根或父级文件占位，检查提示与无路径泄漏、无目录创建及源归档保持不变。已有目标根与恢复漂移继续由原测试覆盖。

验证：`dotnet build --no-restore` 零 warning/error，`dotnet test --no-build` 报告 571 项通过（Infrastructure 330），`git diff --check` 通过。沿用的两项符号链接 fixture 在本机 Windows 无创建权限时提前返回，Unix CI 必须执行。无 schema 变更；跨平台结果以本提交 CI 为准。
