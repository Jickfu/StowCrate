# M5.3 Transfer Protocol / Progress Kernel 自审

日期：2026-09-03；基线：`3589c4bd513a1ec8946fa385bc4209ac01c54a38`。这是 M5.3 的实现检查点，不是整体完成评审。

本次冻结 Plan-scoped transfer 协议并实现 Application 的 immutable progress kernel。核对 `BACKUPPLAN.md` 18.3 的“全量目标发布后才提交 layout”、已有 root relocation 和 baseline/version 不变规则，没有改为逐 artifact 提交。

自审结论：纯进度层没有发现剩余阻断项，不能据此宣布物理迁移已可用。

- `Restore` 验证完整阶段组合，拒绝未知 enum、无效 identity/integrity、重复 version、缺失 staged identity 与提前 cleanup。
- proof 绑定 transaction、Plan、ArchiveVersion、SHA-256/length、native identity 和两类 durability；TargetDurable 必须沿用之前记录的 staged identity。
- 自审补充拒绝不同 artifact 复用同一 native object，并增加恢复/正常转移两条路径的回归测试。相同 bytes 不构成共享对象许可。
- 多 artifact 必须全部 TargetDurable 才能 seal；metadata commit 前没有 old-copy cleanup transition，commit 后只能前进，不存在 rollback transition。
- immutable snapshots 保留原进度，便于 repository CAS 与稳定边界取消。空 copy set 仍必须显式经过 metadata commit；根级 proof 由未来完整 manifest workflow 验证。
- progress kernel 不持有 baseline/ArchiveVersion mutation API，不执行 filesystem/SQLite 操作；`MarkMetadataCommitted` 和 `RecordOldCopyAbsent` 是适配器验证后才能持久化的结果，不是物理操作授权。

本次新增 17 项测试（含遍历全部 aggregate/artifact stage 组合的矩阵测试）。后续必须实现完整 journal schema、repository transaction/CAS/root reservations、physical copy/identity/durability、恢复编排及真实跨平台故障测试，不能把纯对象恢复测试称为进程重启或断电验收。
