# M5.3 Linux 目标比较适配器自审

目标是补齐已批准的只读比较能力，不扩展迁移产品行为。生产入口没有手动选择比较规则或强制继续参数，不创建探测文件。适配器仅支持 Linux x64/arm64 的 ext2/3/4 目录，且必须未启用 casefold/fscrypt；其他组合继续明确拒绝。

## 依据与实现

ext 的 casefold 是目录属性，不能按 Linux 默认值或根目录推断所有子目录。依据 [Linux ext4 文档](https://cdn.kernel.org/doc/html/latest/admin-guide/ext4.html)、[UAPI flags 定义](https://github.com/torvalds/linux/blob/master/include/uapi/linux/fs.h) 与 [ext4 继承规则](https://github.com/torvalds/linux/blob/master/fs/ext4/ext4.h)。原生查询使用同一 no-follow 只读目录句柄执行 fstatfs、FS_IOC_GETFLAGS、statx AT_EMPTY_PATH，不读原始磁盘、不改属性。只在支持的 64-bit ABI 使用对应布局；句柄由 SafeFileHandle 释放，原生缓冲区在 finally 释放。

应用于全部 final/temp 的目录链。现存目录分别查询，缺失目录按最近现存 ext 目录的无 casefold 继承规则处理；缺失不会产生创建操作。两次集合观察涵盖父目录 identity 和首个缺失目录，随后再次检查全量占用。查询结果与当前路径 identity 不一致、目录新增/替换、能力丢失或不同目标目录路径 alias 均拒绝。严格 UTF-8 验证和 component 字节限制防止编码替换或事务 temp 超长。已有完整 observation 与 transaction-bound namespace 校验继续生效。

## 测试与限制

注入测试覆盖支持矩阵、未知子目录、root/parent 替换、观察期间新增目录、规则变化、错误 identity、取消、空根、temp 长度。原生测试覆盖只读目录查询，Linux 成功后进一步验证大小写和 Unicode 字节区别及精确占用拒绝；未知文件保持原样。CI 的 Ubuntu job 必须进入成功分支，不允许将 unavailable 当作通过；Windows/macOS 验证明确拒绝。测试创建文件仅为 fixture 设置，不属于生产探测。

尚未实现 Windows/macOS 及其他 Linux 文件系统比较模型；没有修改 Stage/恢复原语或构造完整 Begin authority。后续完整启动编排必须重验能力，不能缓存本次结果用于复制。现有竞争检测不构成 hostile race 或跨目录原子快照保证。真实 casefold 挂载和 arm64 ABI 尚需专门验收，不将模拟 flags 测试等同于已实测这些环境。

本地验证：dotnet build --no-restore 零警告/错误；dotnet test --no-build 报告 619 项通过（Infrastructure 378）；git diff --check 通过。本机为 Windows，原生 Linux 成功分支证据须以本提交 Ubuntu CI 为准。

首轮 CI 33837346886 的 Ubuntu/macOS 各有同一项测试断言失败：超长 temp 的 namespace 查询先抛出 PathTooLongException，而测试误要求精确 IOException。生产路径已正确拒绝且未写入；Linux 原生比较测试通过。修正为接受 IOException 子类，并新增缺失父目录场景以独立覆盖适配器自身的字节长度检查，不放宽生产行为。
