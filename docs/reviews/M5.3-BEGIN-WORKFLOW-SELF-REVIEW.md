# M5.3 显式 Begin 用例自审

StorageRelocationBeginWorkflow 只负责新事务预检和单次原子 Begin，成功返回 PREPARED。不复制、不执行恢复，不将部分 Inspect 观察转换为可缓存的公开启动凭证。调用方选定 transaction UUID；实际 manifest 使用 v2，无 execution 占位摘要，配置 checkpoint 继续由仓储原子冻结。

预检覆盖一致 inventory、旧 bytes/identity、容量、真实目录比较语义、final/temp namespace 与现存目录 barrier。所有物理 I/O 后重读配置和 metadata，阻止预检期间停用或相关漂移。目标根必须存在；缺失提示创建但程序不创建。平台能力替身仅用于组合协议测试，不扩大原生支持或宣称未来写权限已被证明。

Begin 调用前失败/取消保持零日志；调用后 I/O、仓储错误或取消保守报告 RELOCATION_BEGIN_OUTCOME_UNKNOWN 并保留原 transaction UUID，不推断回滚、不重试。损坏异常保持显式失败。仓储成功返回后不再检查 caller cancellation。恢复需用户选择原事务，App/CLI 入口仍待装配。

真实文件与 SQLite 测试覆盖正常 Begin 后完整迁移/cleanup/compaction、目标根缺失、缺少/不可用屏障、预检取消、目标占位、预检期间停用、数据库回滚、提交后响应丢失、成功提交后取消。响应边界包装器只允许单次 Begin，其余方法拒绝，验证没有自动查询、复制或重放。既有 Inspect/InspectTargets 测试保留，预检不可创建归档临时文件。
