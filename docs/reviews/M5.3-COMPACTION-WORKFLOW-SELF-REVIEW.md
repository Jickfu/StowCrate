# M5.3 显式 compaction 用例自审

已有仓储事务负责全量日志、reservation、binding、placement 及物理 completion 重验和原子释放。本次只补 Application 显式用例与结果分类，不改变 schema、物理删除或仓储事务边界。

调用方必须指定 PlanId、transaction UUID 和正 revision；读取后发现选择改变则拒绝，不重新选择最新日志。未完成返回 NotReady，缺少物理 completion adapter 返回 AdapterUnavailable，不自动恢复。初次无日志返回 NotFound，不把历史缺失当作本次成功。

仓储返回成功即 Compacted，成功后不再响应 caller cancellation 或追加可能失败的读取。异常后只进行一次不可取消读取，不重试 mutation。精确原 COMPLETED 日志仍存在返回 Retained；读取失败、缺失、替换或 revision 改变返回 OutcomeUnknown。初读或重读发现损坏继续抛出，保持与现有 recovery 的 fail-closed 边界一致。诊断不输出底层异常或设备路径。

Application 测试覆盖成功后取消、提交响应丢失、读取不可用、日志/revision 替换、不完整状态、选择漂移、缺失及损坏。真实 SQLite/文件组合测试覆盖成功后重复调用、旧文件/temp 重现、缺少适配器、reservation 删除中的数据库故障回滚、物理检查后取消及过期 revision。失败保留精确 revision 和两条 reservation，新 binding/baseline/归档 bytes 保持；未知文件不删除。

本次没有增加自动 compaction，也未接入 App/CLI。成功只表明本次日志和 reservation 已由现有事务释放，不承诺之后的文件健康或不会发生新迁移。全阶段仍为 IMPLEMENTING。

验证：dotnet build --no-restore 零警告/错误；dotnet test --no-build 报告 657 项通过（Application 118、Infrastructure 398）；git diff --check 通过。物理组合测试沿用注入 barrier，不扩大真实断电持久性保证。
