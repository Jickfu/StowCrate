# M5.3 只读物理检查自审

基线 `6a58d0329a4791119c66c0f2f31650f4e473b351`，基线 [GitHub CI](https://github.com/Jickfu/StowCrate/actions/runs/33830446808) success。本次沿已冻结协议接入只读检查，不改变 migration/schema、ArchiveVersion、baseline 或迁移成功点。

Application 按 configuration → metadata inventory → physical observation → configuration revalidation → metadata inventory 重读顺序执行。重读检查覆盖 Plan/device、roots 和全部 retained placements；无关名称变化可继续，layout/placement 漂移、配置不可读及新出现的维护互锁拒绝结果。流程不调用 Begin、复制、清理或 compaction。

Infrastructure 复用既有 no-follow/native identity 和流式 SHA-256/length 检查，只读取 manifest 之前的 inventory 条目。旧/新根必须存在且不是同一对象；目标父目录不存在时不创建，父目录为文件或链接时拒绝。已有同内容目标仍拒绝，未知的无关文件保留。容量 observation 绑定已捕获的目标根 identity，返回前重新验证全部根和旧对象 identity 以及目标 absence，防止后续 I/O 期间较早对象被替换。

物理结果独立命名为 `StorageRelocationPhysicalInventory`，不包含 durable proof 或可直接 Begin 的 manifest。目标真实 case/encoding collision、事务 temp namespace、写入/barrier capability、目标布局中的 filesystem 边界和完整用户入口仍待完成。根容量观察不是实际空间预留；identity recheck 不证明原对象未被原地改写，不承诺跨文件瞬时快照。后续 Begin/Stage/commit 必须保留独立现场验证，不能缓存此结果作为授权。

验证包含真实文件损坏/缺失、同内容目标占用、父目录为文件、容量未知/不足、取消、空集合旧根离线、容量 I/O 期间旧/新根与旧对象替换、目标重新出现，以及 SQLite 配置/placement/maintenance 漂移。链接与 dangling ancestor fixture 在 Unix 必须实际执行；本机 Windows 缺少创建 symlink 的权限，只有特定权限异常使这两项 fixture 提前返回，不能把本地通过计数当作链接场景已验收。
