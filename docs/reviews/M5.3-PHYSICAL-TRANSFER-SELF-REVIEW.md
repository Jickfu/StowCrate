# M5.3 物理 pre-commit transfer 自审

基线：`02ae863a241ecf5613c41eecacbc4351528dd8b7`。本次仅接入复制与目标发布适配器，不是 M5.3 completion review。

检查点：目标必须 CreateNew/no-overwrite；源根、目标根及普通祖先 no-follow 验证；源和 temp/target 的 native identity 与完整 SHA-256/length；file flush 与 directory barrier；staged proof 必须先 durable record；rename 后中断只按同一 native object 恢复；namespace mutation 后不被 caller cancellation 截断证明收敛；任何失败不删除原归档或未知 temp。

自审修正：temp identity 必须在 CreateNew 后、流式复制前捕获，不能在关闭文件后才认领同路径的替换对象。Windows temp 使用只共享读，允许 identity probe 但不允许其他 writer/delete；POSIX 继续通过前后 no-follow identity 检测正常替换漂移，不宣称绝对 race immunity。

测试覆盖 nested Unicode copy/publish、既有相同内容目标拒绝、rename 后 barrier 失败与同对象恢复、不同对象相同 bytes 拒绝、root replacement、barrier 不可用、损坏输入、预取消，以及真实平台 barrier 的成功或 fail-closed 路径。注入 barrier 只证明控制流，真实跨卷和突然断电尚未验证。

再次自审修正：目标祖先目录即使已存在，也必须完成父目录 barrier，防止上次创建目录后 barrier 失败，重试仅凭目录存在便漏掉持久化。新增中断后重试回归测试。

本地验证：`dotnet build --no-restore` 0 warning/error；`dotnet test --no-build --no-restore` 全部 396 项通过（含 9 项物理迁移测试）。

尚缺完整 preflight/运行编排、metadata commit、post-commit cleanup、Output Reorganization 和启动恢复。上层不得把构造的内存 journal 当作已持久化授权，也不得在目录 barrier 不可用时降低要求。结论：当前适配器边界可继续集成，M5.3 保持 IMPLEMENTING。
