# M5.3 容量阻断自审

基线 490e0778704c2b44ef152b82c4d2127b95dadfdd，基线 GitHub CI success。维护者已确认：无法可靠查询目标空间必须阻止，不提供强制继续。本次把决定同步到 PRODUCT、ARCHITECTURE 和维护协议。

Application 独立 guard 按卷合并复制 Length 下界，同卷多次观察取最小可用值；没有旧副本释放抵扣。checked 防止总和溢出。未知/负值、查询异常、身份无效或根漂移均不放行；取消传播，诊断不泄漏异常内的设备路径。容量检查不承诺空间预留、metadata/allocation 开销或其他进程不会继续写入。

Infrastructure 查询实际目标目录所在卷，而非盘符根。Windows 使用当前调用用户的可用 bytes（支持挂载目录和 UNC）；Unix 以实际目录路径查询。native device/volume identity 分组，前后重验根 identity。卷标识冲突可能造成保守合并，不把碰撞解释为空间增加。依据：[GetDiskFreeSpaceExW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw)、[Unix DriveInfo 源码](https://source.dot.net/System.IO.FileSystem.DriveInfo/System/IO/DriveInfo.UnixOrDefault.cs.html)。不声称基于路径的多次观察是抵抗恶意并发替换的原子快照。

Stage 在任何目标目录/temp 创建前重查全部 Pending 需求；已经 staged 的 bytes 不重复计费，rename/cleanup 不追加容量要求。真实 SQLite 恢复链路在容量失败时返回具体诊断，并保留旧 binding、baseline、journal revision 和旧文件；目标不写入。未更改 schema、归档格式、identity 或 baseline 规则，未触碰真实备份。

范围边界：提供 inventory 可调用的只读容量检查和实际复制门槛，不宣称完整物理 Preview、Begin 用户入口或 M5.3 已完成。低层 Begin 仍是 metadata journal 事务，完整 preflight 编排后续接入。
