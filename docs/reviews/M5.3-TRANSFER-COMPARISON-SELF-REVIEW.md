# M5.3 物理执行比较能力接入自审

原有只读比较检查未进入物理执行链。本次将已批准的未知能力阻断策略落实到默认 Stage、PublishTarget 和 VerifyForCommit；构造函数缺省使用原生比较适配器，不依赖调用者先执行 Preview。

## 边界

新增 VerifyLayoutAsync 接受 immutable manifest，检查全部根和条目的实际目录比较能力。它不调用空目标检查，不把比较能力当作文件 ownership。这样已记录 staged 或已 rename 的恢复不会因本事务文件存在而被错误拒绝；原有 identity/hash/temp absence/no-overwrite 检查继续独立执行。

Stage 在首次写入目录前、父目录创建与 barrier 后分别重验全布局。Publish 在入口、rename 前、rename 后 barrier 完成时重验；后者使用不可取消 token，失败保留已持久化 staged identity，不签发新 proof。VerifyForCommit 在全量哈希/barrier 前后重验，最终仍检查整个 namespace identity。检查结果不缓存为后续动作权限。

Resume 保留能力不可用的稳定诊断。失败不改变旧 binding/baseline，不释放 reservation，不删除未知文件。已提交 cleanup/compaction 的 exact-object 授权边界保持原协议；本次不增加独立删除授权、不改 schema 或旧 journal。

## 验证范围

新增故障测试覆盖 Stage 首次/建目录后、Publish 前/rename 前/rename 后、Commit 首尾及 rename 后取消。多条目测试要求另一条目的不支持目录阻止当前条目复制。真实 SQLite 流程覆盖 Prepared/Staged/Sealed 与 rename 后失败：保留 revision、旧 binding/baseline，并在能力恢复后仅用原 journal 完成恢复。

既有 transfer fixtures 通过显式测试 factory 注入原生能力查询替身，其余真实目录遍历、identity、路径长度、复制和 SQLite 仍执行；不将此替身当作 Windows/macOS 的原生比较支持。新增默认 Stage 测试在 Ubuntu CI 强制成功，在不支持的平台验证创建目录/temp 前阻断。完整 Begin 用户入口、Windows/macOS 比较模型及 Output Reorganization 仍待实施，M5.3 不标为完成。

本地验证：build 零警告/错误，全量测试报告 633 项通过（Infrastructure 392）。最后的布局投影整理及默认原生 Stage→Publish→Commit-check 测试扩展后，再次 build 与 141 项相关测试通过；git diff --check 通过。Linux 默认原生执行成功分支仍由本提交 CI 强制验收；注入 barrier 不扩大实际断电持久性保证。
