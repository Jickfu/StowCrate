# M5.3 复制前目录持久化检查自审

在实际目录容量修正之后，继续前移 Stage 已知能力不足的失败点。归档直接位于 root 时，原路径没有父目录创建步骤，可能到复制完成后才首次发现目录 barrier 不可用。本次在 archive temp 创建前检查实际父目录 barrier，并在返回后重验 source identity、目标根/祖先与 final/temp absence，再响应取消。

该操作不修改 directory barrier 的平台实现，不扩大平台保证，不把探测当成写入成功或可持久复用的 proof。文件数据 flush、post-copy barrier、rename barrier 和 metadata commit 重验仍保留；post-copy 失败的 fixture 调整注入次数，继续验证无 ownership temp 不被自动重用。旧副本删除后的 barrier 故障测试保持原失败点。

新增 root-level fixture 覆盖能力不足、探测期间 temp/target 出现、source 同内容替换、root 替换和取消；均要求不创建本次 temp、不覆盖未知文件，旧归档保持。路径探测基于既有 native identity/no-follow，仍不宣称抵御所有主动替换竞态。根内父目录可能已由既有 Stage 创建，不把失败宣传成无任何目录变化。

验证：build 零 warning/error，全量测试报告 598 项通过（Infrastructure 357），`git diff --check` 通过。取消 fixture 已验证 barrier 返回后取消不会创建空 temp。沿用的 Windows 链接 fixture 权限限制不变；跨平台证据以本提交 CI 为准。
