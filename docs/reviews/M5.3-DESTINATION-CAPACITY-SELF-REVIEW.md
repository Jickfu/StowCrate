# M5.3 实际目标目录容量自审

基线 `3d4e2bc539645a2354abc96e92b3d1eb52b1a813`。原物理检查和 Stage 仅查询新输出根，不能覆盖归档实际写到根下其他卷的情况。本次逐条解析 final/temp 最近现存父目录并查询其所在卷，复用 Application 的同卷合并、最小观察值与未知/不足阻断。

解析不创建目录，逐级拒绝链接/特殊对象；需求携带目录 native identity，容量查询后重新解析整个集合并比较路径/identity/长度。新目录出现或父目录替换时拒绝旧观察。Stage 仅计 Pending，不向已有 staged/target durable 重复收费；空 inventory 根仍查询零需求。未新增 mount 操作或权限要求，未放宽 Windows reparse/no-follow 限制。

测试在私有目录注入不同 volume identity，验证根空间足够而目标父目录不足时 inspection/Stage 均失败、两个目录同卷合并和异卷独立、查询期间新建或替换父目录失败且不写 temp。注入卷映射不冒充真实挂载卷或断电验收；native capacity probe 沿用实际目录查询。原有目标出现 fixture 因同时新增父目录，现在更早被 capacity topology 重验拒绝。

无 schema、baseline、ArchiveVersion 或迁移成功点变更。容量仍为瞬时 bytes 下界，不能承诺空间预留或抵抗所有主动并发挂载替换。真实 case/encoding capability 与完整 Begin 入口继续待办。

验证：build 零 warning/error，全量测试报告 592 项通过（Infrastructure 351），`git diff --check` 通过。沿用链接 fixture 的 Windows 权限限制不变；跨平台结果以本提交 CI 为准。
