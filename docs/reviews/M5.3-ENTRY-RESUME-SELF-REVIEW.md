# M5.3 单条目恢复事务自审

基线：`4a90eda7cc888a305f79f2564c94da33204d03ef`，基线 CI 已通过。本轮新增 ResumeRelocationEntryAsync，未接入整条 Application 显式恢复编排，不改变启动时 pre-commit 只报告待恢复的行为。

入口通过事务内 no-op revision CAS UPDATE 显式获取 SQLite 写锁，再读取完整 durable journal。只有 Pending/Staged 与 durable configuration checkpoint 才进入物理动作；旧 binding、完整 placement/ArchiveVersion、reservation/root safety 和 maintenance 互锁都先重验。相同 revision 的竞争调用仅一个能够进入 Stage。单个大文件 I/O 持有数据库写锁是当前保守实现的吞吐限制，未声称并行吞吐优化。

Stage/PublishTarget proof 返回后忽略 caller cancellation，校验 proof 并持久化进度；不因配置在 I/O 期间漂移而丢弃已取得的 ownership 记录，最终 commit 仍独立重读配置。复制后数据库故障可能留下未记录 native identity 的 temp，下次拒绝接纳、不自动删除；rename 后数据库故障则仍有 staged identity，下一次验证同对象目标后补记。旧根、旧归档和 baseline 不在该入口切换或删除。缺少 checkpoint 的 legacy journal 不补签。

新增测试覆盖 normal/revision/legacy/configuration/取消后的 proof 持久化、竞争调用，以及真实文件/SQLite 的 copy 与 rename 后写库失败窗口。既有真实组合测试改用新事务入口，继续覆盖从复制到清理和 compaction 的原有流程。没有操作真实用户备份；注入 barrier 只验证控制流，不宣称突然断电或真实跨卷验收。
