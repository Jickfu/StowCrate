# M5.3 事务目标命名空间自审

基线 `a250f03838d451d62f72cef02aa1dd8e375481f1`。本次实现 transaction-specific temp 检查与实际 Stage 的全量 Pending 防线，不改变 schema、迁移成功点或 ownership 协议。

新只读入口要求非空拟用 transaction ID 和显式 namespace probe；调用顺序为 configuration/inventory/physical → target/temp namespace → configuration/metadata 重验。输出仅携带 ID 与观察，不用虚构 ExecutionSemanticDigest 拼出可启动 manifest。probe 拒绝不完整的 physical observation，并检查全体 final/temp 字面重名、父子冲突、已占用路径与 no-follow 父目录。不会创建缺失目录、采用同内容目标或删除未知 temp。

Stage 在任何输出写入前检查全部 Pending 条目，后项 target/temp 占位也会阻止首项复制。已有 staged temp 继续按 durable ownership 恢复，不按未知文件删除或重复要求目标为空。现存目标根 native identity 在检查前后重验；真正复制仍保留原有逐对象验证。

范围限制：字面冲突检查不代表真实 filesystem case/encoding collision 已完成，完整 Begin 入口仍不能放行。调研确认目录比较行为需要平台能力观察，不能仅按 OS 名称决定：[Apple pathconf](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/pathconf.2.html)、[Linux inode flags](https://www.man7.org/linux/man-pages/man2/ioctl_iflags.2.html)。未据此新增猜测性 fallback，也未修改只读 Preview 契约。

验证：build 零 warning/error，全量测试报告 586 项通过（Infrastructure 345）；随后增强 staged 与 Pending 共存的 fixture，重新 build 并运行该项通过。覆盖后项占位阻止首项复制、temp 文件/目录占位、根漂移、取消、计划内 target/temp 冲突、缺失 observation 条目、事务 ID 传递及 namespace 检查期间配置漂移。`git diff --check` 通过。沿用的符号链接 fixture 在 Windows 无权限时提前返回，Unix CI 实际执行；最终跨平台证据以本提交 CI 为准。
