# M5.3 Relocation Pre-commit Journal 自审

基线：`358490c74340d06de00022e986ed99e13f83b220`。日期：2026-09-03。

本检查点只完成 root relocation 的 pre-commit 持久化与互斥，不是整个 M5.3 的完成评审。

## 已检查的边界

- Begin 在同一个 SQLite transaction 内重验 device、active registration、old binding、全量 tracked Current/History placement 与 immutable integrity；同时写入 immutable manifest、初始 progress 和 root reservation 投影。
- root set 包括 selected slot 的 inactive unit retained placement，不按 portable declaration 过滤；其他 Plan 尚有 publish/retention/cleanup 工作时，其活动根也计入冲突检查。
- 同 Plan 普通绑定、authority/activation、Secret/FILE_MANAGED identity、publish、retention selection 和 metadata-only reorganization 均不能绕过挂起 journal；跨 Plan binding/activation/publish 检查 reserved roots。
- public progress port 只提供 staged、target 和 seal，按 revision CAS；没有任意覆盖进度或标记 metadata committed 的方法。
- canonical closed-world codec 拒绝缺字段、未知字段、重复字段、未来协议、digest mismatch 与非法 progress；主行 identity/device/stage 和 reservation 投影必须与 manifest 一致。跨 Plan reservation 查询也调用完整校验，不将损坏视为空集合。
- v4 migration 是 additive；旧迁移未修改。future-version snapshot 测试改为当前支持版本 + 1，避免 schema 增长后失去“未来版本”测试含义。
- 故障注入验证 intent 保存后、reservation 保存前失败时全事务回滚；progress 保存后、commit 前失败时 revision/proof 一同回滚。重开数据库后仍保留旧根、Current 与 baseline。

## 自审修正与剩余范围

自审增加了 inactive pending recovery 根冲突保护、metadata commit 的 reservation 检查，以及 reservation 查询中的统一 corruption error 转换。进度 enum 固定数值编码，不能以未来枚举重排改变旧 payload 语义。

本次没有 physical root/leaf probe、实际 copy/rename/delete、File-backed commit-time semantic re-read、Output Reorganization manifest、metadata switch 或 startup orchestration。manifest 中 native identity 和 semantic digest 由未来 physical/Application preflight 提供；目前不能用构造内存 proof 的测试代替物理事实验证。没有 App/CLI 用户入口，也没有 journal delete/abort/compact 逃生接口；保留这些边界直到下一检查点实现安全恢复。

结论：pre-commit 持久化边界可继续接入物理适配器；M5.3 保持 IMPLEMENTING，不宣布 COMPLETE。

本地验证：build 零警告/错误；387 项测试通过（Core 81、Application 70、Archiving 50、Infrastructure 176、Architecture 10），其中新增 relocation journal 测试 21 项；EF `has-pending-model-changes` 无漂移，`git diff --check` 通过。三平台 CI 以本检查点推送后的 run 为准。
