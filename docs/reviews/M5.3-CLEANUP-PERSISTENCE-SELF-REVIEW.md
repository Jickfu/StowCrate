# M5.3 旧副本清理持久化自审

基线：`f08999b3fd9d78ee8092ae405d72e3412a91254d`。本轮只实现 schema v6、逐项清理日志持久化与完成前 absence 重验；不宣称 M5.3 完成，不开放启动自动恢复、compaction 或用户迁移入口。

repository 在 SQLite 事务内按 transaction/revision 加载并校验完整 journal/reservation，重验新 binding、完整 Current/History placement 和 ArchiveVersion、跨 Plan 根占用及 maintenance 互锁，再调用物理清理。返回 proof 必须匹配 transaction、Plan、revision、artifact 与 old-root/old-object/target identity；不得把外部提交的布尔完成标记当作删除证据。部分条目完成不允许提前 COMPLETED，非法调用属于 concurrency/state conflict 而非数据库损坏。

成功物理 proof 后忽略 caller cancellation 写入 progress。数据库故障回滚日志但不回滚新根，重开后可按物理 absence 再证明并补记。完成前逐项重验已清理的旧路径；重新出现的文件绝不再次删除。完成仍保留全部根 reservation、journal 和普通 mutation 互锁；独立 reconciliation/compaction 待后续实现。提交后不重新读取外部配置文件作为清理前提。

v1/v2 reader 与既有 payload 保持原契约；v3 通过 kernel restore 和 canonical bytes 校验。v5 已提交 journal 可跨升级保留，v6 有清理记录时拒绝降级 v5。EF 按 migration 分别提交：无 v3 的 v6 -> v5 可以成功，即使随后的 v5 -> v4 被 configuration checkpoint 拒绝，也不能声称全部降级已回滚。

测试包含 7 类串证据、7 类删除前权限/集合拒绝、部分 Current/History 清理、清理后重开/禁止降级、真实文件与 SQLite 的正常完成、删后写库故障恢复、删后取消和旧路径重现。组合测试注入目录 barrier，仅证明控制流与进程级恢复，不冒充断电或真实跨卷证明。没有操作用户真实备份。
