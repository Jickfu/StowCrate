## 安全边界

- config.db v5 在原始 manifest 之外保存 canonical configuration checkpoint + SHA-256；authority/path 与迁移 identity/layout fingerprint 同 Begin transaction 固定。legacy NULL checkpoint 不补签、不允许提交；旧 ExecutionSemanticDigest 不重解释。
- progress v1 仍仅支持 pre-commit，progress v2 仅支持 MetadataCommitted + 全部 TargetDurable。独立 migration 保留旧日志与 reservations；降级不得丢弃已有新配置 checkpoint。
- Commit 使用 expected Revision，重验 device/journal/reservations、active authority/config、完整 placement/version、old binding、跨 Plan source/output roots 与其他 pending work。物理全量验证在 SQLite transaction 内执行，随后重读 File-backed 文档；事务保持数据库事实不变，但不宣称消除主动文件系统竞态。
- 一个事务更新选定 Current/History root path/key 与 journal progress/revision。ArchiveVersion、timestamp、baseline、relative placement、layout、旧文件和所有 reservation 均保留；不开放 cleanup/compaction。
- 提交前允许取消；进入最终 CommitAsync 后忽略 caller cancellation，避免已提交后误报取消。文件验证期间持有数据库事务会延长写锁时间；优先保证当前边界正确，不把后续性能优化伪装成已完成。
